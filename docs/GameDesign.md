# ニセサツ（仮）コンセプト v0.1

## 一言で
**誰かが作った偽札を、世界の誰かが見破る。** 偽造者と鑑定士の非対称対戦を、非同期UGCで回すゲーム。

## 前提
- 通貨は**架空**（例：架空国家「ルメリア」の紙幣「ルーメ」）。実在紙幣は一切使わない。
- 偽造工程は**抽象化**する。面白さの源泉は「技術の再現」ではなく「どこにコストをかけ、どこで手を抜くか」の読み合い。

## 見た目のトーン
**リアル寄り。**紙の質感・細密な彫刻風の線・落ち着いた色で、本物らしさの中の小さな違和感を探させるため。
ただし図柄・配色・寸法は実在紙幣に寄せず、架空通貨として独自にデザインする。

## 紙幣の構造（ゲーム的抽象化）
1枚の紙幣は数個の「セキュリティ要素」の集合。各要素に**再現度（0〜3）**がある。

| 要素 | 見るための道具 | 備考 |
|---|---|---|
| 図柄・肖像 | 目視 | 常に見られる。手を抜くと即バレ |
| 色味 | 目視 / 比色カード | |
| 記番号 | 目視＋台帳 | 重複・規則違反で判定 |
| 透かし | 透過ライト | |
| 微小文字 | ルーペ | |
| UVインク | UVライト | |
| ホログラム | 傾け操作 | 高コスト |

シーズンごとに要素が増える（改刷）＝いたちごっこのメタ構造。

## コアループ

### 偽造者フェーズ（非同期・1セッション5〜10分）
1. 予算と工房の設備が与えられる
2. 要素ごとに再現度を決める（素材購入＋短いミニゲームで精度が上下）
3. 「ロット」（例：偽札5枚）を市場に流す
4. 後日、結果が返ってくる：何人を騙せたか、どの要素で見破られたか

**読み合いの核**：鑑定士の道具は回数・時間が限られる。
「どうせUVは毎回は使えない」と読んでUVを捨て、目視要素に全振りする、など。

### 鑑定士フェーズ（1セッション3〜5分）
1. 窓口に紙幣が次々来る（本物と、他プレイヤーの偽札が混在）
2. 1枚あたりの持ち時間と、道具の使用回数（UV 3回、ルーペ 5回…）に制限あり
3. 受理 / 拒否を判断
4. **本物を拒否するとペナルティ**（客のクレーム）→ 全部疑う戦法を封じる

### スコア
- 偽造者：騙せた人数 × 額面 − 製造コスト
- 鑑定士：正解数、誤拒否・見逃しでマイナス
- 両ロールに別々のレート。偽札自体にも「通過率」から難易度レートが付き、鑑定士の実力に応じて出題される

## なぜ面白いか（仮説）
- 偽造者は「人間の鑑定のクセ」を読む。鑑定士は「人間の偽造のクセ」を読む。AI相手では生まれない読み合い。
- 問題（偽札）がプレイヤーから無限に供給される。
- 自分の偽札が「今日○人を騙した」という通知が、再訪の動機になる。

## 将来モード
- リアルタイム1v1（同じ窓口で、片方が作って片方が見る）
- 中央銀行ロール：新しい防止技術を設計する第三の役

## 技術・公開先
- **Godot 4 で開発し、unityroom に Web 書き出しで公開**
- Web 書き出しはスレッドなし（Godot 4.3以降の single-threaded export）にして、SharedArrayBuffer がなくても動くようにする
- unityroom 側に UGC の保存先はない。非同期対戦をやるときは外部バックエンド（例：Supabase）を HTTPRequest で叩く。それまではローカルで完結させる

## MVP範囲（提案）
1. **鑑定士フェーズ**：CPU が自動生成する偽札で遊べる（1人用として単体で成立）
2. **偽造者フェーズ**：作った偽札を保存し、鑑定側に出題する
3. **ホットシート対戦**：1台で交互にプレイ。サーバーなしで「読み合いが面白いか」を検証できる
4. 面白ければ外部バックエンドを足して、非同期UGC対戦にする
