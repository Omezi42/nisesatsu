## M1: 鑑定士モードを1人用として仕上げ、公開する
**ねらい:** 「道具の回数をどこに使うか」で悩めるか、結果画面で次に何を見るべきか学べるかを、外の人に遊んでもらって確かめる。

### 作ること
- [ ] 道具の回数を ルーペ4・透過3・UV2 に変える(GameDesign.md 第6章)
- [ ] フォーカスが外れたら持ち時間を止める一時停止画面(第6章)
- [ ] 研修シフト(6.2節): `shift_training.tres`、固定の紙幣の並び、ヒント表示、タイトルの「研修」「本番シフト」
- [ ] ベストスコアの保存と表示(第6章)
- [ ] Web書き出しプリセット(GL Compatibility・スレッドなし)
- [ ] 書き出した pck に対してヘッドレステストを回す仕組みを `check.sh` に足す
- [ ] unityroom へテスト公開(アップロードはユーザー)
- [ ] 書き出し手順が固まったら `.claude/skills/` にビルド用 Skill として切り出す

### 次へ進む条件
- Web版で1シフト通して遊べ、`check.sh` が書き出し版も含めて ALL OK
- 遊んだ人の感想で「道具の使いどころに悩んだ」「結果画面で見落としが分かった」が得られる。得られなければ M1 内で道具・得点・CPUの偽札を調整する

## M2: 偽造者モード
**ねらい:** 「どこにコストをかけ、どこで手を抜くか」を1人でも試せるようにする。M3 で人間同士にする前に、CPU鑑定士を相手に作る側の面白さを確かめる。

### 決めること(GameDesign.md 第7章「詳細は鑑定士モードの試作後に決める」)
- [ ] 1ロットの枚数・予算・報酬(騙せた人数 × 額面 − 製造コスト の具体値)
- [ ] ミニゲームの中身(結果を±1ぶれさせる程度。現実の手順に寄せない抽象的な操作にする)
- [ ] 流した先の鑑定士を誰にするか。1人用では **CPU鑑定士**(道具の回数を持ち、どの要素を見るかに癖がある)が要る。その癖を何種類用意するか
- [ ] 返ってくる情報の粒度(「どの要素で見破られたか」をどこまで見せるか)

### 作ること
- [ ] `Banknote` の保存形式(`user://` への保存と、将来サーバーへ送る形を同じにする)
- [ ] 偽造の規則(予算で再現度を買う・ミニゲームのぶれ)を `scripts/core/` に純粋なクラスとして切り出す。CPUの偽造(`BanknoteFactory`)と共有する
- [ ] CPU鑑定士(`scripts/core/`)
- [ ] 偽造画面・ロットの結果画面
- [ ] 作った偽札を鑑定士モードに出題できるようにする(自作の偽札を自分で見る)

### 次へ進む条件
- 「目視に全振り」「UVだけ本物」など、作り方によって CPU鑑定士への通り方がはっきり変わる
- 遊んだ人が2ロット目で作り方を変える

## M3: ホットシート対戦
**ねらい:** 人間同士の読み合いが面白いかを、サーバー無しで確かめる。**ここが非同期UGCへ広げるかどうかの判断点。**

### 決めること
- [ ] 1試合の形(各自が何枚作り、何枚見るか。役の交代回数)
- [ ] 本物と偽札をどう混ぜて出すか(全部偽札だと読み合いにならない)
- [ ] 画面の受け渡し(相手の作った内容を見せない「端末を渡してください」画面)
- [ ] 勝敗の付け方(偽造者と鑑定士の得点をどう比べるか)

### 作ること
- [ ] 試合の進行(`scripts/core/`)と画面
- [ ] 試合結果(どちらがどの要素で読み勝ったか)

### 次へ進む条件
- 2回目以降の試合で、相手の見方を読んで作り方・見方を変える場面が出る
- ここで面白さが出なければ M4 へ進まず、要素・道具・得点を見直す

---

## M4: 非同期UGC対戦
**ねらい:** 誰かが作った偽札を、世界の誰かが見破る(GameDesign.md 第1章)。

### 決めること・調べること
- [ ] バックエンド(GameDesign.md 第10章の例は Supabase)。Web版から HTTPRequest で叩けるか(CORS)
- [ ] unityroom の規約上、外部サーバーとの通信・ユーザー投稿をどこまで扱えるか
- [ ] 本人の識別(匿名ログインで足りるか)
- [ ] 不正対策: 偽札の再現度・判定・得点は**サーバー側で同じ `scripts/core/` の規則で再計算**する。その実装言語(GDScript をそのまま回せないなら移植の範囲)
- [ ] 出題の選び方とレート(GameDesign.md 第8章)
- [ ] 投稿に自由文字列(名前・ひとこと)を入れるか。入れるならフォントのサブセット(Pitfalls.md)と表示の審査

### 作ること
- [ ] オンライン用の保存形式・API
- [ ] 偽札の投稿と、他人の偽札の取得・鑑定・結果の送信
- [ ] 自分の偽札が何人を騙したかの通知・一覧
- [ ] 両ロールのレートとランキング

### 次へ進む条件
- 投稿された偽札が実際に遊ばれ、通過率に偏り(簡単すぎ・難しすぎ)が出たらレートで出題が調整される
